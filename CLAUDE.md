# Rezka TV — заметки для Claude Code

Неофициальный клиент rezka для Android TV: родной ExoPlayer вместо плеера сайта, ТВ-интерфейс на leanback.
Пользовательская документация — README.md, сторонние компоненты — THIRD_PARTY.md,
регламент качества и его план — docs/quality-roadmap.md.

## Устройство, под которое всё делается
- TCL на Android TV 9 (API 28), Realtek RTD284x (4× Cortex-A53), **32-битный ARM, 1,4 ГБ RAM** — слабый:
  всё меряется на нём.
- ADB по Wi-Fi: `adb connect <ip>:5555` (при первом подключении с нового компьютера подтвердить на ТВ).
- Release + AOT после каждой установки: `adb shell cmd package compile -m speed -f dev.alaev.rezkatv`.
  Debug-сборка на ТВ в 2–3 раза медленнее — замеры только на release.

## Планка качества (обязательна для любой задачи)
«Должно работать быстро и быть удобным, как rezka»: холодный старт < 1 с, отклик на кнопку < 100 мс, без рывков;
в отчёте — цифры (`adb shell dumpsys gfxinfo <пакет>`, время запуска) с release-сборки. Оформление: янтарный акцент,
белая скруглённая рамка фокуса с увеличением, только D-pad, «Назад» предсказуем, интерфейс на русском.

## Сборка и проверка
- `./gradlew verify` — все быстрые проверки одной командой, как в CI.
- `./gradlew testDebugUnitTest` — юнит-тесты (JUnit 4, `app/src/test`, фикстуры в `app/src/test/resources`).
- `./gradlew assembleRelease` — `app/build/outputs/apk/release/app-release.apk`.
- `python3 -m unittest discover -s tools` — тесты `tools`.
- JDK 17, Android SDK platform 36. `local.properties` (sdk.dir) — свой на каждой машине, не в git.
- Ключ release — `keystore.properties` в корне (не в git); без него — отладочный ключ. Обновление на ТВ
  встаёт поверх только с тем же ключом, иначе удаление = потеря входа в rezka и прогресса.
- `app/src/main/assets/lists/top.json` (рейтинг IMDb) — не в git и не распространяется: `tools/build_lists.py`.

## Архитектура вкратце
- `rezka/` — клиент сайта (jsoup, кэш страниц на диске), `rezka/player/` — Media3 + leanback,
  `rezka/login/` — вход с телефона по QR (LAN-страница), `rezka/lists/` — «Рейтинг» и «Оскар».
- `session/` — «Продолжить после выключения», синхронизация прогресса с сайтом.
- `RezkaActivity` — режим «Сайт» (WebView) как запасной вариант.
- Логи: `adb logcat -s RezkaTv`.

## Правила
- Ничего тяжёлого: без больших фреймворков, без Compose; фон — корутины.
- Не коммитить: `top.json`, ключи, `keystore.properties`, `local.properties`.
- Коммиты — по-русски, «Область: что сделано».

## Принципы сопровождения (по докладу Е. Бугаенко, ITGorky, 17.10.2026)
- **Без комментариев.** Во всём коде (Kotlin, Python, Gradle, XML, YAML, proguard) никаких комментариев
  и докстрингов; понятность — именами и маленькими функциями.
  Существующие комментарии удаляются при правке файла. Сборка падает на любом комментарии.
- **Оживлять, а не переписывать.** «Legacy» нет: устаревшее (зависимости, накопленные недочёты) отдаётся
  агенту целиком и приводится в актуальное состояние.
- **Агент мержит сам** небольшое и зелёное изменение. Радикальное — плеер, вход, ключи подписи, схема
  хранения прогресса — оставляется на ручную проверку владельцу.
- **Изменение ≤ 200 строк** (добавлено + удалено), иначе сборка красная и изменение делится на части.
  Фикстуры в `app/src/test/resources` и журналы долга `quality/*-baseline.xml` не считаются.
- **Нулевая терпимость.** Всё, что считаем низким качеством, превращается в автоматическую проверку,
  а не в договорённость.
- **Наглядность.** Тесты сравнивают результат с текстовыми снимками рядом с фикстурами, чтобы изменение
  поведения было видно по изменению снимка без чтения кода (прежде всего парсер: страница → снимок разбора).
  Формат снимка — любой удобный.
- **Польза, а не дифф.** К каждому изменению — отчёт: размер APK, строки кода, число тестов, а с ТВ —
  холодный старт и `gfxinfo`.
- **Главная ветка всегда зелёная** (здесь — в отличие от доклада: изменений единицы, а не сотни в день).

## Код
- Неизменяемость: `val`, неизменяемые коллекции, без глобального изменяемого состояния.
- Классы маленькие; композиция вместо наследования (кроме обязательных классов платформы).
- Исключения не глушить: перехват — только там, где ошибку действительно обрабатывают.

## Тесты
- Один тест — одно поведение; имя теста — предложение о поведении.
- Без сети: всё внешнее — фикстуры. Фейки вместо моков. Без общего изменяемого состояния между тестами.
- Каждая ошибка начинается с падающего теста; нестабильный тест чинится сразу.

## CI/CD
- В `main` — только через pull request с зелёной проверкой; проверка — одна команда, как на любой машине.
- Сборка падает на любом предупреждении компилятора и lint.
- Выпуск release — одной командой, без ручных шагов (кроме ключа из `keystore.properties`).
